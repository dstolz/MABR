# Quality audit — 30 October 2026

A whole-repository review of MABR for correctness, robustness, speed and usability, with the defects it found either fixed on the branch `qc/audit-fixes` or listed below with a recommended fix. The review read every package under `+mabr/`, the legacy `abr_analysis/` pipeline, the launchers, examples, helpers and docs, and mined the daily logs in `.error_logs/` for failures seen on the rig. Eight independent read-only audits were run in parallel (one per area) and their findings were cross-checked against the code and, where it mattered, reproduced numerically in MATLAB before anything was changed.

## 1. Where the code stood (baseline)

`run_all_verifications` on `master` (R2025a, 894 s): **55 of 60 passed**. The five failures were real regressions, not flaky tests:

| Script | Cause |
| --- | --- |
| `verify_online_advance`, `verify_live_refresh`, `verify_compute_worker` | `mabr.ui.LivePlot.requestWindow` was declared in a private methods block, but `mabr.ui.AcqController.setLivePlot` calls it. Every Start in the real app took the same path. |
| `verify_live_plot` | `LivePlot.MultiCondition` had been moved into a private properties block; the test reads it. |
| `verify_stimgen_import` | `mabr.stim.fromStimgen` asserts on `StimType.IsMultiObj`, a property the current stimgen pin has removed. Every bank import failed. |

All five are fixed (section 2.1).

## 2. What was fixed

Everything below is on `qc/audit-fixes`; nothing is committed. Each change carries a comment at the site saying why, in the style the code already uses.

### 2.1 Build regressions

- `+mabr/+ui/LivePlot.m` — `requestWindow` is public again; `MultiCondition` is readable (`SetAccess = private`).
- `+mabr/+stim/fromStimgen.m` — the `IsMultiObj` check is guarded with `isprop`, so the current and older stimgen pins both import.

### 2.2 Accuracy of the processing code

- **Signal-to-noise ratio read 6 dB low everywhere.** `mabr.metrics.snr`, `mabr.data.Recording.noisePower` (hence `Block.Metrics.snr` saved in every `.abr`) and the online *Residual noise* metric used the odd-minus-even difference of the two half-averages as the noise estimate. That difference has four times the variance of the noise left in the grand mean; the plus/minus reference is half of it. Simulated: pure noise read −5.4 dB where an unbiased estimator reads 0 dB. All three now halve the difference, and `noisePower` returns NaN with fewer than two clean sweeps instead of reporting one sweep as 0 dB SNR. Consequence for existing files: their stored `Metrics.snr` is 6 dB lower than values written from now on.
- **Saved sweep onsets sat one ADC sample early.** `Pipeline.finalize` and `io.buildStruct` mapped a raw onset `o` to `round(o/df)`, but `resample` puts raw sample `1+(j-1)·df` at ADC sample `j`, so the right index is `1+round((o-1)/df)`. Every saved sweep therefore began about 78 µs (at 192/12 kHz) before its stimulus and every offline latency read long by that much, unless the analyst clicked *Use it* in the analysis Settings. Fixed at the source; `Config.DataVersion` is now `'26B'`, `AbrFile.read` returns the file's `DataVersion`, and `SettingsDialog.onsetBiasOf` reports 0 for files written at `'26B'` or later so the correction cannot be applied twice. Reader cache version bumped (`AbrFile.ReaderVersion = 2`), so the first catalog scan after this change re-reads every file once.
- **Intermixed runs were filtered across sweep joins.** For an interleaved/shuffled run, each stimulus's trace was *compacted* (sweep windows laid end to end) and then `filtfilt` was run over the compacted trace, ringing a step the size of the EEG jump between neighbouring windows into the first milliseconds of every sweep — where waves I and II are — and so the artifact flags saved in `ADC.IsArtifact` and `Block.Metrics` did not mean what a conventional run's did. `finalize` now filters the continuous trace once and cuts raw and filtered traces with the same windows (`Recording.withProcessed`). One pass instead of one per stimulus.
- **Live preview and saved artifact verdict disagreed with the high pass off.** The live preview demeaned each sweep before the voltage test; finalization did not, so a run on a DC offset showed 0 rejected live and then had every sweep flagged in the file (and, with Repeat set, make-up runs appended for all of them). Finalization now applies the same rule.
- **Peak picking took the first *n* wiggles, not the *n* most prominent.** `mabr.metrics.find_peaks` passed `'NPeaks'` to `findpeaks`, which stops at the first *n* local maxima in time order. The organizer's *Mark peaks* marked noise ahead of wave I, and the inspector's auto-detect and the online latency metric, which rank by prominence, only ever saw the first few candidates of their window. It now returns the *n* most prominent, in time order.
- **Threshold statistics** (`+mabr/+analysis`):
  - `SeriesThreshold`: the "loudest level" exemption for the next-louder metrics used `max(levels)`, which on a descending (attenuation) axis is the quietest level — every descending series earned spurious "metric undefined" flags. Now judged with the level direction.
  - `SeriesThreshold.bootstrapCI`: censored replicates (no response at any level) were dropped before the percentiles, biasing the upper limit low (a quarter of replicates right-censored still gave a finite upper limit). They are kept; an end at infinity is reported open (`CIOpen`, flag `bootstrap CI open`).
  - `SingleTrial.splitHalf` in median mode took the median across both polarities of a half; a polarity-locked cochlear microphonic made it bimodal and r fell from 0.24 to about 0. The median is now taken per polarity and averaged.
  - `SingleTrial.features`: the leave-one-out template included rejected sweeps, so one 500 µV pop added ~1 µV to every other sweep's template and `TemplateR` collapsed exactly where rejection had worked. The template is built from clean sweeps only; a rejected sweep is projected onto the clean mean.
  - `PermTest`: a one-pass variance that rounds negative gave a complex t; clamped. The two `sortrows` per TFCE step and per cluster-mass pass were replaced by a transpose-ordered `find` that pairs run starts and ends without sorting — bit-identical output, measured 2.4× faster on a 512×180 null block.
  - `Filter.design`: custom coefficients stamped for another sample rate are refused instead of silently applied with scaled corners.
  - `Session.segment`: sweeps dropped for a non-finite sample were also counted as "ran off their file"; counted before that pass now.

### 2.3 Data loss and acquisition robustness

- **A failed save no longer loses the run.** `AcqController.assemble_blocks` called `writeABR` with no guard, so a full disk, an unplugged drive or an over-long filename threw out of the loop, abandoned every block of the run not yet written, skipped the viewers, and the ring — the only other copy — was reset by the run already streaming. Each file is now written in its own `try`; the block is still added to the session and shown, and the failure is kept in `LastErrorMessage` for the main window.
- **A next run that cannot start no longer discards the finished one.** `conclude_run` started the next run before assembling the finished one, with no guard; a `tooLong` or device error there threw past the assembly. The finished run is now built and saved first and the failure raised after, with the state set to Error.
- **Atomic file writes.** `.abr` and `_STIM_` files are written to a `.part` beside the target, checked to read back, and renamed into place (`io.saveAtomic`), so a crash mid-write cannot leave a truncated file under the final name (which every catalog scan then retried). Variables over 1.9 GB go to `-v7.3`. The notes journal is written the same way, in UTF-8.
- **The compute workers survive a bad cycle.** `compute_loop` had one `try` around its whole loop, so a window the publish buffer could not hold, a condition table over its cap or a throwing metric ended the worker; the client learned of it only after 5–10 s of silence, relaunched into the same inputs, and wrote the role off for the session. Each cycle now has its own `try`, the error is reported through the queue, and the worker carries on. The handshake is sent after the buffers are mapped, and a user metric that throws on the worker is now logged (once per slot and message) instead of leaving unexplained NaN gaps.
- **Live time base ≥ 85.4 ms killed the DSP worker.** The window clamp was off by one sample (the inclusive `0:df:w` window is one sample longer than `w/df`), so the published sweep exceeded `MaxComputeSamples` and the worker died on the publish. Clamp corrected in `AcqController.setSweepWindow`.
- **Calibration refused after a finished schedule.** `engineHoldsDevice` tested `State ~= Idle`, but a completed schedule leaves `SchedComplete` and a failed one `Error`, so *Settings ▸ Calibration…* and the input calibration said "stop the running schedule" when nothing ran. Both now use `ProgState.isTerminal`.
- **The wrong diagnosis for a device that would not open.** Every "Timing pulse not detected… check the wiring" in the 2026 logs followed a worker error (an interface switched off, an invalid device name). `start()` now reports the worker's error when there was one and blames the wiring only when the self-test block completed without a pulse.
- **Advance after Abort no longer cancels the abort** (`stopBlock` cleared `HaltAfterBlock`).
- **The worker refuses commands it used to swallow.** A Prep/Run/Release/Resume polled mid-stream was consumed silently and the client waited forever; the frame loop now answers with `mabr:acq:worker:busy`.
- **Schedule checks.** A stimulation-only run is no longer refused for exceeding a ring buffer it never writes; a run whose stimulus leaves less than the detector's re-arm gap (0.5 ms) before the next onset is warned about in red at render time, since fused timing pulses mis-pair every later sweep and the alignment report only names it afterwards. The ring-cap message now says how long the run plays and how long the recorder holds, rather than sample counts.
- **Window changes no longer re-read the whole block.** Typing a live time base reset onset detection and re-read every sample of the run so far (about 230 MB and a second for a 5-minute run, in-process and on both workers); the onset list is kept and only the windows are re-cut.
- `ComputeEngine.setJob` clears a slot's custom function when a catalog metric replaces it, so a later stall is not blamed on a built-in.
- `mabr.data.io.buildStruct` writes `ABR_Data.Subject` (the ID as typed); see 3.2 for why.
- `Config.verifyToolboxes` prints `>= v9.11`, not `>= v9.1`.

### 2.4 Launchers, tests and docs

- `MABR.m` / `MABRAnalysis.m`: the path filter was `contains(p,'.git')`, a substring test that drops every folder under a root such as `…\.gitrepos\MABR`, and `genpath` added twenty folders of non-code (`docs`, `plans`, `.error_logs`, `.runtime_data`, the submodules' `tests`, `documentation`, `templates`). The filter is now anchored to path components and excludes those; MABR's own `tests/` stays on the path.
- `run_all_verifications` prints each script's time, lists the failures by name at the end, and returns a results struct (`Name`, `Passed`, `Seconds`, `Message`) so a build job can `assert(all([R.Passed]))`.
- Docs: the README said R2019b (the GUI needs R2021b), Troubleshooting said five required toolboxes (four), Installation and Testing showed `4 / 4` and `24 / 24` verifications (60). The API reference now points at the `+mabr/+analysis` reference page, which it omitted entirely. `Config.MaxComputeSamples`'s comment said 85 ms (it is 85 ms of baseline plus 85 ms of response).

### 2.5 Legacy pipeline (`abr_analysis/`), examples, helpers

- `extractABRResponses` kept only the **last** file of a condition (`S{sidx} = nan(...)` per file), so Loop/Repeat passes and `_2`/`_3` same-second files silently vanished: three files of 100, 100 and 7 sweeps gave 7 columns. Sweeps now accumulate in start-time order with one warning per pooled condition; files with different sweep lengths are refused clearly. **Compact files** (intermixed runs: sweep windows laid end to end) are refused with a pointer to `mabr.analysis.Session` — read as a continuous trace they produced a phantom peak at −6 ms and 4 µV of "pre-stimulus" mean.
- `abrPermutationThreshold`: a level with one trial crashed the whole call (`Non-scalar in Uniform output`); such levels now get NaN p-values and are excluded, and NaN p-values no longer become significant detections through `min(max(NaN,0),1)`. `isotonic` compared an unbounded cluster mass with a criterion in [0,1] and returned the lowest level for any noise cluster; it now defaults to the binary target. A failed fit reports `minimum (fallback)` instead of claiming `(glm)`.
- `permtest`: variance clamped (a constant trial gave a complex t); an optional `Seed` so results reproduce (p was 0.08/0.05/0.11 on identical data); the TFCE step loop is capped at 1e5 steps (near-noiseless Test Mode files made it a hang of ~1e9 iterations); the help no longer claims the statistic compares against the baseline.
- `rejectArtifacts` discarded the **quietest** sweeps too (two-sided `isoutlier`); upper tail only by default, `tail="both"` kept as an option; the help listed methods the validator refuses; matrix input works as documented.
- `plotABRGrid` accepts the current `U.Level`/`U.Frequency` (kHz) as well as the old `soundLevel`/`frequency` (Hz).
- `helpers/Fsp.m` computed something that was not Fsp (pooled single-sweep variance over an un-normalised denominator: 1.09 for noise and 1.08 for a real response); now Elberling & Don's `var(mean)/(var(point)/N)`.
- `examples/quick_analysis.m` added only the repo root to the path (so the logger was never found) and pointed at the author's personal data folder; `curate_thresholds.m` shadowed `quit`. `docs/Offline-Analysis.md` now states the chain's real dependencies (the author's `helper_fnc` repository, Statistics and Curve Fitting toolboxes), that `filterABRData` is a second filtering pass, that compact files are unsupported, and cuts the response window before testing as the author's own batch script does.

### 2.6 Analysis window (`mabr.ui.AnalysisApp`, `Model`, `View`, `NoteEditor`)

- **Unsaved edits were discarded without a word** when the results folder was read-only, unreachable or showing a conflict and the user opened another session, another folder, or closed the window (`flush()` does nothing in those states). `Model.leaveSession` now asks *Discard / Stay* (default Stay) at every one of those doors, including the review queue's.
- The floating **note editor kept targeting the previous session**: series keys are shared across sessions, so a note committed after clicking another session landed on the same-keyed series of the new one. It now records the session, closes on a session or folder change, and refuses to commit to a different session.
- **Ctrl+Z in a text field undid the last curation** instead of the typing; the editing chords now fall through to text components.
- **Busy stuck after Ctrl+C**: `runJob` had no `onCleanup`, so an interrupted job left every later edit saying "Busy" and the close box inert.
- A cancelled startup restore printed "Dot indexing is not supported" (`Catalog` empty); guarded.
- A failed tab refresh was only logged and the tab left half-drawn with `Dirty` cleared; it now reports to the status line and retries on the next activation (the 6 Oct `Filter` error in the logs behaved exactly like this).
- The results-file stamp was taken **after** a load that can take minutes, so a write by another process during the load was stamped as ours and overwritten by the next autosave; taken before now.
- Export from the Study tab defaults to the sessions in the study rather than the single open session.
- **Re-exporting into the same folder duplicated the raw tables** (`mabr_trial_waves.csv`, `mabr_blocks.csv`, `mabr_block_waves.csv`, the per-session Parquet files and `mabr_export.mat` all append); `Model.exportWork` now clears its previous raw outputs first (18,213 rows stayed 18,213 instead of doubling).

### 2.7 Acquisition main window (`mabr.ui.App`)

- **Closing the window mid-run asked nothing** and killed the worker with the run. The close box now asks "A run is in progress. Closing now will lose the data of this run." with *Keep recording* (default) and *Abort and close*; `delete(app)` is unchanged for scripts, and a `ConfirmFcn` hook keeps tests headless. A close during a Start is deferred until the Start returns.
- The status line (one 22 px label, ~65 characters) now carries its full text as a tooltip and takes a level (grey/warning/error); the red *Error* lamp is accompanied by `ERROR: <reason>` from the controller's new `LastErrorMessage`, where before the last "Saved…" text stayed on screen.
- Preference writes on teardown (`WindowPos.remember`, `rememberValue`) are guarded: a corrupt `matlabprefs.mat` — seen in the logs, and reproduced when several MATLAB sessions rewrite it — used to stop the window closing or read as "Start failed".
- After *Per stimulus…* repetitions the field showed the first count as if it were everyone's; the tooltip and panel title now say `min–max` and that typing overwrites every stimulus.

## 2.8 Second pass (31 October 2026): the items of section 3 taken up

Asked to complete the recommendations below, the second pass landed the following (section 3 now lists only what remains).

**Acquisition**

- **Nearest-onset pairing and a saved alignment record** (3.1.1). `Pipeline.finalize` pairs by order as before, but when a spurious or lost pulse has broken the order it pairs each recovered pulse with the nearest planned onset (`pairOnsets`, fed the plan's `ExpectedOnsets` by both the DSP worker and the in-process path) and logs what it dropped. The engine watches its parfeval future (`afterEach` → `WorkerError`), the controller's aux tick ends a run in `Error` when the worker is gone or the ring head stops for 3 s, and a device call that throws mid-block ends the block (reason `deviceError`) so what was recorded is finalized and saved, with the schedule halting in `Error`.
- **One streamer per runtime folder** (3.1.3). `Engine.run` takes `stream.lock` with its process id; another live process's Run is refused with the remedy; a dead owner's lock is taken over.

### 2.12 Offline statistics (second pass)

- **Detection tests ± pair averages** (`Threshold.detect` → `Threshold.pairPolarity`, `Settings.DetectPairPolarity`, default on). Pairing the k-th positive with the k-th negative sweep within each file cancels the cochlear microphonic before the sign-flip test. Simulation (500 runs, 160 sweeps, CM 2–4σ, TFCE, 200 permutations): power with a CM 0.754 → 0.970, with none 0.978 → 0.974; false positives 0.044 / 0.040 at α 0.05. An edited condition is re-tested with the options its results were made with.
- **The Firth fit sees only levels connected to the top response** (`Settings.GLMConnectedOnly`, default on) and flags "isolated detection below threshold": the isolated-false-positive series moves 21.7 → 34.1 dB (descending rule 35), a series with two misses below 33.6 → 55.6, and a series whose top two levels are silent reads no-response instead of 20 dB; every series without an isolated detection is bit-identical. In the real-data fixture only the 16 kHz series moved (56.3 → 65.8; descending 65).
- **The split-half bootstrap partitions first**, then resamples within each half and polarity (`SingleTrial.splitHalf(Bootstrap=true)`); on noise alone the replicate mean r is −0.004 where resampling first gave +0.33.
- **Duplicate levels** are flagged ("repeated level at L dB") and collapsed to one entry per level (an override first, else the strongest evidence), so two entries at the top level no longer hide the "top-level-only run" flag.
- The **Firth profile interval** interpolates the deviance crossing between grid points (deviance at the ends 3.8416/3.8418 against the cut 3.8415).
- `means()`, `grid(Reduce="mean")`, `plotStack` and `Plot.*` draw the **polarity-balanced mean** the measurements use (`Polarity="all"` keeps the plain one).
- `measure` reads the typed `LevelParam`/`LevelDirection`/`GroupBy` when `analyze` runs it (see 3.2.2 for the residual).
- Tests: `verify_offline_session` Part F now compares the nulls against PermTest on the paired sweeps (and checks `PairPolarity=false` reproduces the raw-sweep null); new checks in `verify_offline_thresholds`, `_stats`, `_session` and `_analyze` cover the simulation, the gate, repeated levels, the interval and the balanced means. `verify_offline_trials` Part F's count of sweeps the test used now allows the pairing's odd remainder.

## 3. Found, not fixed

What the two passes deliberately left. Each needs a design decision or a change wider than this review should make; the items fixed in the second pass have moved to section 2.8–2.12.

### 3.1 Acquisition

1. **The live path decimates by striding without an anti-alias filter** (`extract_sweeps`), while finalization uses `resample`. Content above 6 kHz folds into the live traces, the artifact preview, `Corr` and the early-stop criterion, but not into the file. Harmless with a band-limited amplifier front end; not otherwise. Recommendation: box-average the `df` samples per output sample in the live path (a 16× larger indexed read per sweep, chunked on a rewind).
2. **The live correlation criterion and the online metrics are still polarity-blind.** `Pipeline.accumulate`'s odd/even split is the polarity split under alternation (conservative: the cochlear microphonic anti-correlates the halves and delays the early stop rather than firing it), and the condition table the metrics worker holds carries no polarity, so the online *Residual noise*/SNR cannot use the balanced reference the saved metrics now use. Recommendation: carry `SweepPolarity` in `ConditionStore` and into the metric context.
3. **Artifact thresholds remain volts at the electrode with defaults of ±100 mV / 30 mV RMS**, which an ABR never reaches; the labels now say so and the gain is in the tooltip. Changing the defaults is a lab policy decision (a gain-1 rig would reject everything at 25 µV).
4. Only one streamer per runtime folder is now enforced; two MABR installations on one machine still share `%LOCALAPPDATA%`-free fixed paths unless `MABR/RuntimeDir` is set per installation.

### 3.2 Offline analysis

1. **Random streams are shared where they should not be.** `Session.measure` and `Session.detect` derive the same per-condition stream, and inside `SingleTrial.summary` the split-half draws from the stream the power test has just consumed, so `SplitR` changes with `NumPermutations` on identical data (0.2274 / 0.2330 / 0.2298 for 0, 200 and 400). Both are pinned by `verify_offline_stats` and `verify_offline_trials` as a documented contract; changing them means changing that contract (salt the measure stream; give the split-half a stream seeded from the shared one before anything else draws). Likewise `Seed` stays mapped to the *detect* step although *segment* reads it under random equalisation.
2. **A thresholds-only re-fit does not re-measure.** `measure` now reads the typed `LevelParam`/`LevelDirection`/`GroupBy` when `analyze` runs it, but the three settings stay mapped to the *thresholds* step (the window's quick re-fit relies on it), so the next-louder pairing behind `XCorrUp`/`DTWUp` follows a changed direction only at the next analysis that runs measure.
3. `prestoFit` weights squared residuals by `1/SD` rather than `1/SD²`; check against the ABRpresto paper before changing.
4. `Model.compareMethods` judges alternation per session (`any(Files.AlternatePolarity)`) where `estimateThresholds` judges it per series, and omits `NumPermutations`, so the comparison table can read "insufficient" where the Thresholds row has a value.
5. `Catalog` still loads every `.abr` in full on a cold scan to read ~1 KB of metadata; a small `ABR_Index` variable written by `io` and read first would make scans a header read. (Notes lookups no longer load files without notes.)
6. `Settings.problems` does not relate `MaxSweepsPerCondition` to `MinSweeps` (the dialog now shows a soft note); a hard refusal was tried and withdrawn because `verify_offline_analyze` caps at 64 under a minimum of 100 on purpose.
7. The new `DetectPairPolarity` and `GLMConnectedOnly` settings change every settings hash, so results saved before this pass read "out of date" at the detect and thresholds steps until re-analysed — intended, but worth knowing before opening a large study.
8. Analysis window: `SessionView`'s "Leave out run group" and "Unit overrides" controls and `GridView`'s detection-override menu have no tooltips (covered by the new Help ▸ Glossary only); `Model.setThresholdValue`'s status text still says "dB" on a non-dB level axis; the Study table's 300 ms debounce is exercised only with `AutoRefresh` on, which no test sets.

### 3.3 Legacy pipeline (`abr_analysis/`)

- `batchABRAnalysis`'s default `filePattern` ends at the timestamp, so same-second `_2`/`_3` files are not matched (and so not pooled) in a batch; `verify_data_roundtrip` pins that default.
- `SCRATCH_BatchABRanalysis.m` is still the author's personal script with hard-coded paths; the docs now point at `batchABRAnalysis` first.
- The penalised GLM's Monte Carlo interval is wide and runs past the tested levels ([−21, 82] dB on the separated fixture where the class's profile interval is [5, 61]); the interval method was documented, not changed.

## 4. Speed

- The verification suite: 894 s on this machine; most of it is parpool start-up and the GUI scripts. The runner now prints per-script times.
- The live view realized 10–12 Hz against a 20 Hz target in the September logs, with ticks up to 1.8 s; the logger's own verdict is "between ticks: other GUI callbacks". The organizer's per-block `drawnow` at the end of an intermixed run while the next streams is the likeliest contributor.
- The DSP worker publishes a full payload every 50 ms whether or not anything changed (the heartbeat), and the client `isequaln`s it at 20 Hz: about 4 MB per read at the caps. A separate heartbeat word and a version in the header would make most reads a header read.
- `evaluateJobs` evaluates live conditions first with a budget that resets every cycle and no cursor, so a slow live metric starves the finished backlog for the whole run.
- `ComputeEngine` keeps every block's sweeps for the session solely to replay on a relaunch, and re-serializes them on the GUI thread per block.
- Fixed in this pass: TFCE 2.4× faster; window changes no longer re-read the block; finalization filters once rather than per stimulus.

## 5. Features worth adding

Chosen from the audits for value to an ABR lab against cost; one line each.

1. **Plan-guided onset pairing and a persisted alignment record** per file (3.1.1) — turns the most dangerous silent failure into a flagged, recoverable one.
2. **Resume after Abort, Error or crash** — a Start variant that skips runs already counted and writes to the same session folder; plus "Save partial run…" from the ring after a device error.
3. **Per-condition running noise and SNR with early stop in intermixed runs** — Welford odd/even sums per condition are O(1) per sweep and make the pooled `Corr` (meaningless when conditions alternate) unnecessary.
4. **Pre-Start checklist**: device present, loop-back pulse height, Output writable with free space, bank calibrated, resulting filename stem, overlap and ring-cap checks, Test Mode said out loud.
5. **Polarity-aware detection** as the default (3.2.1), with a CM-variance diagnostic flag per condition.
6. **Censor-aware thresholds**: a Firth fit restricted to levels connected to the top response, and intervals that carry censoring (3.2.2–3).
7. **Template/DTW-guided wave tracking** from a subject-specific template at the loudest level, with per-pick confidence.
8. **Flag-driven review queue** in the analysis window (non-monotone, wide CI, methods disagreeing first) with a "k of n left" counter and wrap-around.
9. **Self-describing files**: `ABR_Data.Subject` (now written), a small `ABR_Index` header for fast scans, and MABR/submodule git hashes stamped into every file.
10. **Session JSON** written atomically at Start and finish (subject, rig, bank, settings, file list) — fixes grouping under per-stimulus folder schemes and survives renames.
11. **Immutable export snapshots** in `exports/<timestamp>/` with hashes in the manifest, instead of appending into old folders.
12. **A `mabr.doctor`** that checks MATLAB and toolbox licences, writable runtime and log folders, submodule SHAs, ASIO devices and a pool start — most Troubleshooting entries would become one command.
